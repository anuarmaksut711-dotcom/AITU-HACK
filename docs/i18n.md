# Interface localization

The web interface supports Russian (`ru`), Kazakh (`kk`) and English (`en`). The Mantine Select
language selector is available on login, in the workspace sidebar, on guest
room pages and on router error pages. The choice is saved as `soyle-locale` in
local storage and synchronized between tabs. With no saved choice, the first
supported browser language is used; unsupported languages fall back to Russian.
Storage being unavailable does not prevent switching within the current page.

`apps/web/src/i18n/{ru,en,kk}.json` contain matching catalogs. Russian source
messages are the typed keys; interpolation uses `{name}` placeholders. Add each
message to all three catalogs. Use complete sentences for text containing values,
so translators can change word order. `t()` translates at call time. Components
that use translations subscribe using `useLocale()`; this rerenders them without
remounting forms or live audio. Module-scope label maps use getters so they do not
capture the language at import time. Validation schemas use error callbacks for
the same reason. `localizeMessage()` is limited to application-owned errors kept
in form or job state; do not apply it to transcripts, meeting titles or AI output.

Calendar labels, date formatting, page titles, metadata, accessibility labels,
modal close buttons and API error adapters follow the interface language. Recording
language remains an independent input. Stored transcripts, names, quotations,
meeting titles, AI answers and exported source data are not translated by changing
the interface language. Print/PDF interface labels use the current language.

## Checks

From `apps/web`:

- `npm run check:i18n`: verify catalog keys, nonempty translations, placeholders
  and translation calls in source.
- `npm run test:i18n`: run isolated browser tests with mocked API responses and a
  Vite server on port 5197. No backend or model credentials are needed.
- `PLAYWRIGHT_CHANNEL=chrome npm run test:i18n`: use an installed Chrome instead
  of Playwright's bundled Chromium.
- `npm run build` and `npm run lint`: type, production build and lint checks.

Browser tests cover locale detection, persistence, storage failure, cross-tab
updates, preserved form drafts, validation and API errors, meeting data, upload,
Kanban/calendar, chat, guest consent and narrow viewports. They do not establish
live audio connectivity or production/provider behavior.
