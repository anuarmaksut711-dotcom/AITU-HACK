# Канбан и итоги встреч

Внутри каждой сохранённой встречи появился раздел «Итоги встречи». Он включает канбан поручений (к выполнению / в работе / заблокировано / готово), представление по содержанию (поручения, решения, темы и тезисы, открытые вопросы, риски), краткую выжимку и редактирование карточек.

Карточки хранятся в PostgreSQL вместе со встречей. У карточки есть ответственный, дата и дословная формулировка срока, приоритет, статус, признак проверки пользователем и цитата. Неозвученные исполнители и сроки остаются неизвестными. Приоритет без подтверждения также остаётся неуказанным. Относительные сроки не вычисляются от текущей даты. Точную дату можно задать вручную. Исходный транскрипт не изменяется.

Можно искать по карточкам, фильтровать ответственного, приоритет, просрочку и непроверенные карточки; архивировать и возвращать карточки через редактор. Перетаскивание дополняет доступный с клавиатуры выбор статуса. На узких экранах колонки располагаются вертикально. Ручные карточки работают без LLM.

## Локальная генерация

Новый модуль использует только Ollama и не наследует облачного провайдера существующего RAG-чата.

- `INTELLIGENCE_LOCAL_URL` — адрес локального Ollama, по умолчанию `http://host.docker.internal:11434`.
- `INTELLIGENCE_MODEL` — заранее установленная локальная модель, по умолчанию `qwen3:8b`.
- `intelligence-worker` — отдельный процесс из Compose, подключён только к internal-сети `data`. Миграция `0004_meeting_boards` создаёт доску и очередь обработки.
- Для отключённого от интернета профиля используйте существующий `compose.rag-offline.yaml`: он направляет генерацию на контейнер `ollama`. Модели нужно подготовить заранее; автоматической загрузки моделей нет.

Стандартный RAG-чат проекта по-прежнему может использовать OpenAI. Для выполнения требования ТЗ о полной локальности всего приложения нужен offline-профиль; локальность нового канбана не превращает существующий облачный RAG в offline-сервис.

Запуск после сборки и настройки локальной модели:

```sh
docker compose build api web
docker compose run --rm migrate
docker compose up -d api intelligence-worker web
```

Кнопка «Разобрать встречу» ставит задание в устойчивую очередь. Страницу можно закрыть. Длинная стенограмма разбивается на перекрывающиеся фрагменты, все символы входа учитываются; выжимка сокращается иерархически. Одинаковые карточки на границе фрагментов объединяются по типу, цитате и заголовку. Семантически похожие формулировки могут потребовать ручного объединения/архивирования.

Каждая цитата проверяется как точный фрагмент входа. Это проверка источника, а не доказательство смысловой точности: неверная интерпретация существующей цитаты всё ещё возможна, поэтому результат ИИ требует пользовательской проверки. Команды внутри стенограммы рассматриваются как данные, а не инструкции для инструментов.

Публикация результата атомарна и сохраняет ручные карточки, добавленные во время обработки. Повторная генерация готовой встречи возвращает уже существующий результат. Обновления защищены версией доски: конфликт не перезаписывает новые правки. После ошибки доступны повторный разбор и ручное заполнение. Прерванное задание восстанавливается по истечении lease с ограничением числа попыток.

## Экспорт

- JSON — весь протокол и карточки, версия формата 1, цитаты, источники и состояние проверки.
- CSV — выжимка и все категории карточек, UTF-8 BOM и защита от формул таблиц.
- Печать / PDF — печатная версия всего протокола; PDF сохраняется через диалог браузера.
- ICS — только подтверждённые и проверенные, незавершённые и неархивные поручения с точной датой. События на целый день; импорты не отправляются во внешние сервисы автоматически.

Экспорты всегда содержат всю доску, независимо от поисковых фильтров. ICS применяет дополнительные условия выше. Данные других рабочих пространств недоступны через чтение, изменение и экспорт. Удаление встречи каскадно удаляет её доску.

## Проверки и границы

Серверные проверки покрывают права доступа, CSRF, миграцию вверх/вниз, сохранение карточек, конфликт версий, восстановление lease, повторный запуск, ручные правки во время обработки, валидацию цитат и неизвестных полей, полноту разбиения длинного текста, локальный адрес провайдера, CSV и ICS.

UI проверяется в отдельной временной базе на явно тестовой встрече. Вывод модели в таких проверках подменён контролируемым тестовым ответом. Это проверяет API, очередь и интерфейс, но не доказывает качество Qwen/Ollama, скорость реального распознавания или работоспособность конкретного offline-развёртывания. 11 сентября 2026 локальный API и intelligence-worker обновлены, миграции применены после резервного копирования. Маршруты канбана и readiness проверены через 8787 и Vite 5173; сохранённая встреча осталась в базе. Локальный Ollama на 11434 недоступен, поэтому генерация реальной моделью пока не проверена.

## Источники, уточнения и изменения договорённостей

Карточки и предложения выжимки могут открывать исходный фрагмент стенограммы с выделенной цитатой и соседним контекстом. Для аудиовстреч временные отметки вычисляются по сохранённым сегментам распознавания; плеер начинает воспроизведение с начала соответствующего сегмента и останавливает выбранный фрагмент в конце последнего сегмента. Это точность сегментов, не выравнивание каждого слова. Для текстовых встреч и несовпадающих сегментов доступна только стенограмма. Имя спикера показывается только при явной подписи в исходном тексте; новая диаризация не добавлена.

Аудио отдаётся через авторизованный `GET /api/v1/meetings/{meeting_id}/audio` с поддержкой Range. Доступ ограничен рабочим пространством, файл не получает публичного URL и не кэшируется. Позиции цитат считаются в Unicode-символах: emoji не сдвигают выделение в браузере. Если цитата повторяется, нужен точный `quote_start` либо более длинный уникальный фрагмент. Автоматического выбора первого совпадения для новых карточек нет.

У поручений и решений есть отдельное поле договорённости: «Согласовано», «Предложение», «Нужно уточнить». Оно не зависит от канбан-статуса и отметки проверки человеком. У старых карточек без этого поля статус остаётся неопределённым, пока пользователь его не уточнит. Отдельный фильтр и редактор показывают отсутствующего ответственного, неозвученный срок, относительный срок без календарной даты, неуказанный приоритет и неподтверждённую договорённость. Приоритет можно оставить неизвестным. Нажатие «Проверено» не подтверждает предложение автоматически.

Локальная модель получает схему истории изменения срока и исполнителя: прежнее/новое значение и обе дословные цитаты. Сервер проверяет совпадения, хронологию, последовательность изменений одного поля и соответствие последнего значения текущей карточке. После извлечения карточек выполняется дополнительное локальное сопоставление явных исправлений; оно может связывать карточки из разных фрагментов стенограммы. Подтверждённое изменение сохраняется в истории актуальной карточки; неразрешённый спор оставляет обе карточки с пометкой «Нужно уточнить». Ручное редактирование не стирает исходную историю. История является серверным полем и не принимается в теле ручного изменения карточки.

Для обычных встреч все кандидаты сравниваются вместе. При объёме кандидатов более 24 000 символов используется предварительный отбор до шести похожих предыдущих заголовков для каждой карточки. Это ограничивает контекст модели, но может пропустить переформулированную договорённость. Совпадение цитат и порядок реплик не доказывают верность интерпретации моделью; ручная проверка остаётся необходимой. Уже готовые доски автоматически заново не генерируются: их прежние ручные правки сохраняются.

JSON и CSV включают историю, источники и уточнения. Печатная версия сохраняет цитаты изменений и пометки. Перед экспортом в интерфейсе можно вернуться к уточнениям либо выгрузить текущий документ с пометками. ICS включает только **проверенные и согласованные** активные поручения с точной датой.

Дополнительной миграции для этих полей нет: расширены JSON-карточки существующей таблицы. Нужно обновить API, web и intelligence-worker вместе. Автоматическое извлечение новых полей требует доступной локальной модели; ручная работа с карточками от неё не зависит.

### Проверки дополнения

`apps/api/tests/test_protocol_evidence.py` проверяет источники и время, Unicode, повторяющиеся цитаты, прежние карточки, сохранение истории при правках, запрет её подмены, календарь предложений, исправления через границу фрагментов, спор без решения, локальность сопоставления и авторизованную частичную выдачу аудио.

Браузерная проверка выполнена на отдельной временной SQLite-базе с явно тестовой встречей: переход к 00:16, выделение цитаты, запуск и остановка воспроизведения около 00:22, сохранение календарной даты и уменьшение списка уточнений. Аудио в этой проверке — синтетический сигнал, а карточки созданы контролируемым ответом провайдера. Это проверка работы интерфейса и API, не качества распознавания речи или интерпретации Qwen. Локальный Ollama в ходе этой проверки не был установлен/запущен; внешние AI API не вызывались.

## Страница встречи

Сохранённые текстовые встречи и аудиозаписи используют формат рабочей области Live: общий заголовок и вкладки «Разговор», «Итоги», «Канбан». Канбан доступен независимо от состояния генерации. Во вкладке «Разговор» находятся исходный текст, временные отметки и аудиоплеер; в «Итогах» — выжимка, договорённости и переходы к разговору, а также раскрываемый чат по встрече. Вкладка сохраняется в URL: `?view=conversation`, `?view=insights`, `?view=kanban`. Это представление сохранённой встречи; оно не включает микрофон или подключение к голосовой комнате.

## Перетаскивание и панель управления

Группировка, поиск, фильтры, создание карточки и экспорт собраны в компактную строку из стандартных компонентов Mantine; на узком экране строка прокручивается горизонтально. Ответственный, приоритет и остальные фильтры доступны в выпадающей панели «Фильтры».

DnD использует dnd-kit и ручку захвата в карточке. В группировке по статусам перенос меняет статус поручения, в группировке по содержанию — тип карточки. Порядок колонок фиксируется при перетаскивании, чтобы они не менялись местами после переноса последней карточки. Порядок карточек внутри одной колонки этим действием не задаётся. Мышь и касание используют один pointer-сенсор; с клавиатуры: фокус на ручке, пробел, стрелка к нужной колонке, пробел для переноса или Escape для отмены.

Во время переноса видны плавающая карточка и выделенная колонка. Изменение показывается сразу и сохраняется существующим API с проверкой версии; при отказе восстанавливается предыдущая доска и загружается актуальное состояние. Браузерные проверки с подменённым транспортом покрывают перенос мышью, клавиатурой и эмулированным касанием, сохранение при перезагрузке, отмену, ошибку сохранения, перенос между типами, управление фильтрами и одну строку кнопок.
